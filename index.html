[ How it works ]

How a task moves through the lab

Same loop in every XYZ project
STEP 01

Claim the issue

Pick a GitHub issue. The task gets its own clone and worktree, so nothing lands on main by accident.

STEP 02

Agents do the work

Several coding agents run side by side on one codebase. Every action they take lands as an ordinary commit.

STEP 03

Review, then merge

A second agent reviews the diff in rounds until it is clean. The PR merges from one place, with the trail intact.

[ Questions ]

Things people ask

Short answers. The long ones live in each repo's README.

Is everything here open source?

Yes. Every project lives in a public GitHub repository under the HiQS-Labs organization. Each repo carries its own license file.

Which coding agents does XYZ Forge work with?

Claude Code, Codex and agy out of the box. The harness talks to agents through plain files and shell scripts, so adding another one is a small change.

Do I need XYZ Forge to use the skills?

No. Skills Army Mini installs skills into whichever coding tool you already use. XYZ Forge adds the multi-agent workflow on top.

Where do I start if I am new?

XYZ mini. It is the smallest version of the workflow and takes one repo and one agent. Move to XYZ Forge when you want more than one agent on the same codebase.

How do I report a bug or ask for a feature?

Open an issue on the project's repo. Issues are the unit of work here, so a clear title and description is the best way to get something built.

Pick a project, open the docs, send a pull request.
